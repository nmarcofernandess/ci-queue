# Etapa 3 S0 baseline

## Lock and scope

This baseline was captured before any S1-S3 read-path patch from commit
`5a9268e41e27644362dfd9e5cd4e163813f5e1a1` (tree
`67da42f17aac27f046995f952ec49ad578bb9712`). The API/records/UI source files
had no working-tree diff at capture time. Concurrent S4 edits were limited to
the installer and its isolated test and do not enter these measurements.

The fixture state was generated only in temporary directories. It did not read
the installed queue, DietFlow, operator logs, arguments, environment or real
registries. OS caches were not purged.

Machine: macOS 26.6.2 build 25G83, Apple M4 (10 logical CPUs), 16 GiB RAM,
Python 3.9.6. HTTP samples used Node v25.6.1 only for environment reporting;
the measured server is Python. Percentiles are nearest-rank.

## Internal work attribution

The separate non-timing counter pass used the exact records blob
`f9d691128e45e8c880ba81343bccf5eade07eb79`.

For D1000H, a warm Executions All request reopened and hashed 1,000 unchanged
bodies (22,205,300 logical bytes) and called recursive progress projection 900
times to return 50 rows. Status All did the same. After changing one ticket,
the base reopened/hashed 1,000 bodies and performed 1,001 JSON reads totaling
22,205,380 logical bytes. These are application bytes, not claims about SSD
physical I/O. The separate reader timing at D1000H was 190.377/209.677 ms
p50/p95 for Executions All and 192.482/211.058 ms for Status All.

The macOS same-size mutation with restored mtime changed ctime and was observed
by the existing digest reader; strict corruption raised `RecordError`, while
permissive reading omitted the corrupt row. A mutation invisible to every
metadata field cannot be detected without reopening the body. S0 therefore
does not claim metadata as cryptographic integrity.

## Baseline product checks

1. Initial `npm run check` exited 127 at build because this isolated worktree
   had no dependencies (`tsc: command not found`).
2. `npm ci` and `npm --prefix ui ci` completed from the lane lockfiles.
3. `npm run check` under the ambient Homebrew Node v25.6.1 built successfully;
   core passed 170/170, then runtime failed 3/43 and the fail-fast check stopped.
   The failures copied the dynamic Node executable without its Homebrew dylib,
   producing `dyld: Library not loaded: @rpath/libnode.141.dylib`; this changed
   expected pass/fail observations and is platform/runtime-fixture related.
4. Repeating `npm run test:runtime` with the absolute canonical Node
   `/Users/marcoantonio/.local/share/dietflow-runtime/node/v24.20.0-darwin-arm64/bin`
   exited 0: 42 passed, 0 failed, 1 explicitly skipped. No DietFlow state or
   code was touched.

## Decisions fixed before optimization

The numeric and structural gates are in `budget-lock.json`. S0 ratifies the
minimal direction: per-file cache and immutable server snapshot; additive
`view=live`; page summary before recursive projection; full detail by ticket;
a small canonical-key client store; and reuse of Worktrees inventory without
changing action validation. SQLite, watchers, WebSocket, a second service,
TanStack Query and slower polling are rejected absent measured need.

## Honest gaps for integrated proof

- No compiled-browser trace, React commit/layout/paint, two-tab, hidden/visible,
  1,000-row interaction or 100-remount memory run is claimed here.
- DWT repositories were generated by the fixture path, but Git/du request
  latency and complete child CPU accounting were not captured in this S0 run.
- The script's DLIVE writes the required 20 queued alternating owners, but the
  running sidecar/two-attempt/emitter-zero variants require integrated proof.
- Metadata/inode/removal/corrupt-JSON behavior was probed; injected permission
  and registry/ledger unreadability remain test obligations for S1/S5.
- No installation, launchctl, login, installed-Mac latency or boot was observed:
  `bootObserved=false`.

These are proof gaps, not permission to reduce population, UI detail, polling
cadence or the locked budgets.
